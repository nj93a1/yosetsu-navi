# レーザー溶接機 比較・選定サイト 要件定義書

サイト名：溶接道場
作成日：2026-09-17
クライアント：ノースヒルズ溶接工業株式会社

---

## 1. 目的

Web上のレーザー溶接情報をコントロールし、潜在顧客が比較検討する段階で
信憑性の高い情報に到達させる。第三者評価として機能させ、
ノースヒルズが販売するレーザー溶接機の販売台数増加につなげる。

達成条件
1. 情報収集系キーワードで検索上位に入る
2. 診断完了者からノースヒルズへ問い合わせが発生する

---

## 2. 決定事項

| 項目 | 内容 |
| --- | --- |
| 運営主体 | 新規の独立サイト。ノースヒルズのブランドは前面に出さない |
| ドメイン | 新規取得。本体サイト・既存LPとは分離 |
| 性格 | 中立的な比較情報サイト |
| 掲載範囲 | 他社製品を含む。特定メーカーに偏らない |
| メーカー名 | 実名掲載可（第8章1を要確認） |
| 商品点数 | 10〜30点 |
| ゴール | 情報提供と購買意欲の向上。受注はノースヒルズ側で対応 |

---

## 3. 運営者開示（必須）

運営者を隠した比較サイトで自社製品を有利に見せる構成は、
景品表示法のステルスマーケティング規制に該当する。以下を必須とする。

1. 全ページのフッターに運営者名を記載
2. 「運営者について」ページに、販売事業者であること、
   一部製品を取り扱っていること、評価基準と情報源を明記
3. 自社取り扱い品に「運営元で取り扱い」ラベルを表示

---

## 4. 想定ユーザー

中小製造業の現場作業者・工場長・経営者。中年以降が中心。
IT操作に慣れているとは限らず、小さい文字や細かい操作が負担になる。
検索段階は情報収集と比較検討が主戦場。

---

## 5. 機能要件

### 5-1. 選定診断（中核）

画面
- 1画面1問、選択肢は最大5つ、全5問
- 進捗表示を上部に固定、「戻る」を下部固定
- 全問に「わからない」を配置。選んでも診断は継続し候補が広がる
- 選択肢は文字に加え母材写真と板厚見本を併記

設問
| 問 | 選択肢 |
| --- | --- |
| Q1 素材 | 鉄・ステンレス / アルミ・銅 / チタン・特殊 / 複数 / わからない |
| Q2 板厚 | 薄板 / 中厚 / 厚物 / 混在 / わからない |
| Q3 使用者 | 熟練工が使う / 新人も使う / これから始める |
| Q4 環境 | 屋内固定 / 屋外含む / 自動化ラインに組込 / わからない |
| Q5 予算 | 100〜200万円 / 200〜400万円 / 400〜600万円 / 未定 |

結果表示
- おすすめTOP5に固定。全件表示はしない
- 各候補に選定理由を1行表示
- 枠配分を固定：1〜3枠は適合度順、4枠は専門用途、5枠は価格重視
- 完全一致ゼロの場合、条件を1つ緩めた候補を提示し緩めた条件を明示
- 「条件を1つ変える」で予算のみ・板厚のみの再検索が可能
- TOP5から最大2台を横並び比較（3台以上は不可）

### 5-2. 商品詳細ページ
- スペック（波長・出力・可搬性・対応素材・対応板厚・価格帯）
- 運営者による選定コメント（1商品1文以上、必須）
- 向いている用途と向いていない用途を両方記載
- 同価格帯の代替候補2件
- 自社取り扱いラベル

### 5-3. 専門用途からの入口
一般診断で埋もれる商品を発見可能にするため、独立メニューをトップに配置。
アルミ・銅・チタン / 真空 / 屋外 / 自動化ライン組込

### 5-4. コンテンツ
- 方式解説記事（TIGとレーザーの違い、方式別の適性）
- 課題別の選び方記事
- 導入インタビュー記事（課題・選定理由・導入後の変化）
- 全記事末尾に診断への導線を固定配置

### 5-5. 問い合わせ
- 診断結果画面に問い合わせ導線、電話、LINEを常設
- 問い合わせ時に診断回答を自動添付

## 6. 商品データ設計

タグ6軸を多重付与する。
1. 用途（薄板接合 / 厚物 / 異材接合 / 補修 / 自動化）
2. 素材（鉄 / ステンレス / アルミ / 銅 / チタン / マグネシウム）
3. 板厚（0.5mm未満 / 0.5〜3 / 3〜6 / 6mm以上）
4. 環境（屋内 / 屋外 / 真空 / クリーン / ライン組込）
5. 価格帯（100万円未満 / 100〜200 / 200〜400 / 400〜600 / 600万円以上）
6. 習得難易度（未経験可 / 経験者向け / 熟練者向け）

運用ルール
- 1商品あたり平均10タグ以上。登録時に下限チェック
- 四半期ごとに90日間候補に上がらなかった商品を抽出し、
  タグ不足か整理対象かを判定

データ項目
商品名 / メーカー名 / 方式 / 波長 / 出力 / 可搬性 / 対応素材 /
対応板厚 / 環境 / 価格帯 / 習得難易度 / 選定コメント /
自社取り扱い区分 / 画像 / 情報源

## 7. UI・計測・技術

### UI（初期状態で見やすく、端末設定の変更を前提としない）
| 項目 | 値 |
| --- | --- |
| 本文 | 18px以上 |
| 見出し | 24px以上 |
| ボタン高さ | 56px以上 |
| タップ領域の間隔 | 12px以上 |
| コントラスト比 | 4.5:1以上 |
| メニュー項目 | 最大5つ |

禁止：ホバーのみの情報表示、横スクロールする表、自動再生の動画・カルーセル
前提：スマートフォン優先設計

### 計測
条件の組み合わせを1レコードとして記録する。
記録項目：各設問の回答 / 表示5商品 / 詳細閲覧商品 / 比較商品 /
問い合わせ有無 / 離脱地点

月次で確認する指標
| 指標 | 用途 |
| --- | --- |
| 条件セット別の検索回数 | 市場ニーズの実測 |
| 詳細閲覧率 | 提示内容の妥当性 |
| 問い合わせ率 | 商品力と価格の妥当性 |
| 該当ゼロの条件 | 品揃えの穴。仕入れ候補 |
| 設問別の離脱率 | 設問削減の判断 |

設問は増やさず、離脱データを根拠に減らす方向で改善する。

### SEO
- ページ表示速度を優先（画像の遅延読み込み、軽量構成）
- 記事は課題ベース、商品ページは「メーカー名＋機種名＋比較」で狙う
- 構造化データ（Product、FAQ、BreadcrumbList）を実装
- Search Consoleを初期から接続し、クエリ実績を見て記事を追加
- 内部リンクは「記事 → 診断 → 商品詳細」で固定

### 技術
- 診断ロジックはタグのマッチングによるスコアリング。条件はコード直書きにしない
- 商品データと選定コメントをクライアント側で更新可能にする
- 商品データはCSV一括更新に対応
- 診断ログを独自に蓄積し、エクスポート可能にする

## 8. 未決事項（着手前に要確認）

1. メーカー実名掲載の可否
   9月15日の打ち合わせでは「複数メーカー取り扱いのWeb公表はメーカー側の意向で困難」
   とされていた。今回の判断と食い違うため、どこまで実名掲載できるか個別確認が必要。
2. 評価スコアの根拠
   実機検証、カタログスペック、ヒアリングのいずれを根拠とするか。
   比較サイトとして機能させるには評価基準の公開が必要。
3. 掲載商品の選定基準
   仕入れ先製品と競合製品の扱いを分けるか。
4. 価格の表示方針（実売価格か価格帯のみか）
5. ドメイン名とサイト名
6. 運営体制（商品データと記事の更新担当、更新頻度）
